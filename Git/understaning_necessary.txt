# Git concepts explained for interviews (Data Analyst level)

## 1. What is Git?

**Interview answer:**

> Git is a version control system that helps track changes in code or data projects. It allows me to save different versions of my work, collaborate with others, and revert to previous versions if something breaks.

**Real-life analogy:**

* Git = Google Docs version history, but for code and data files.

---

## 2. What is a repository?

**Interview answer:**

> A repository, or repo, is a folder that Git tracks. It contains the project files and the entire version history.

**Example:**
If you have:

```
sales_analysis/
   ├── analysis.ipynb
   ├── data.csv
   └── README.md
```

When you run:

```
git init
```

This folder becomes a **Git repository**.

---

## 3. What is a commit?

**Interview answer:**

> A commit is a snapshot of the project at a specific point in time. It helps track what changes were made and when.

**Example:**
You:

* Clean the dataset
* Add charts
* Save changes

Then:

```
git commit -m "Cleaned missing values and added bar chart"
```

This becomes a **saved version** of your project.

---

## 4. What is a branch?

**Interview answer:**

> A branch is an independent line of development. It allows me to work on new features or experiments without affecting the main project.

**Simple analogy:**

* Main branch = final report
* New branch = draft version of analysis

---

## 5. What is a Pull Request?

**Interview answer:**

> A pull request is a request to merge changes from one branch into another. It is used for reviewing and discussing changes before adding them to the main project.

In teams:

* You create a branch
* Make changes
* Create a pull request
* Teammates review it
* Then merge it

# Now the checklist explained (interview-ready)

---

## 1. Push a project to GitHub

**Meaning:**
Upload your local project to GitHub.

**Interview explanation:**

> I use Git to track my local changes and GitHub to store the remote version. I commit changes locally and push them to GitHub so they are backed up and shareable.

---

## 2. Pull updates from a repo

**Meaning:**
Get the latest changes from GitHub.

**Interview explanation:**

> I use `git pull` to synchronize my local project with the remote repository, especially when working with teams or updating shared files.

---

## 3. Create and switch branches

**Meaning:**
Work on a new feature separately.

**Interview explanation:**

> I create a branch when I want to experiment or add a new feature so the main branch remains stable.

Example:

```
git branch feature-eda
git switch feature-eda
```

---

## 4. Merge a branch

**Meaning:**
Combine changes from one branch into another.

**Interview explanation:**

> Once the feature or analysis is complete, I merge the branch into the main branch so the changes become part of the final project.

---

## 5. Resolve a simple conflict

**Meaning:**
Fix situations where two versions of a file clash.

**Interview explanation:**

> A merge conflict happens when the same part of a file is modified in two branches. I manually choose the correct version and then commit the resolved file.

Example conflict:

```
<<<<<<< HEAD
Total = revenue
=======
Total = revenue - discount
>>>>>>> feature-branch
```

You edit it to:

```
Total = revenue - discount
```

Then:

```
git add .
git commit -m "Resolved merge conflict"
```

---

# How to answer “How do you use Git in your projects?”

Use this exact structure:

> I use Git to track changes in my analysis projects.
> Typically, I create a repository, commit changes after each major step like data cleaning or visualization, and push them to GitHub.
> When working on new features, I create a separate branch and merge it into the main branch once it’s complete.

---

# One perfect 20-second answer

If they ask: **“Do you know Git?”**

Say:

> Yes, I use Git for version control in my projects. I usually create repositories, commit changes after major analysis steps, and push them to GitHub. I also use branches to work on new features and merge them into the main branch once they’re complete.
